# Incident Management Brain

이 문서는 AI가 운영 상의 장애나 포스트모템을 분석할 때 반드시 지켜야 하는 SRE(Site Reliability Engineering) 원칙입니다.

## 1. Blameless Culture (비난 없는 문화)
장애 분석(RCA)을 수행할 때, "개발자의 실수", "작업자의 오타" 등 사람을 탓하는 분석을 절대 금지합니다.
*   대신, **"왜 시스템이 그 실수를 허용했는가?"**에 집중하십시오. (예: "CI/CD 파이프라인에 문법 검증 단계가 누락되어 있었다", "안전장치(Guardrail) 없는 직접 DB 접근 권한이 부여되어 있었다")

## 2. 5 Whys 기법
근본 원인(Root Cause)을 찾기 위해 '왜'라는 질문을 최소 5번 반복하며 깊숙한 시스템적 결함을 찾아내십시오.
1. 왜 서비스가 다운되었나? -> DB 커넥션 풀이 고갈되어서.
2. 왜 고갈되었나? -> 특정 슬로우 쿼리가 커넥션을 물고 놓지 않아서.
3. 왜 슬로우 쿼리가 발생했나? -> 새로 배포된 기능에 인덱스가 누락되어서.
4. 왜 누락을 몰랐나? -> 리뷰 과정에서 Explain Plan을 확인하는 절차가 없어서.
5. 왜 절차가 없었나? -> DB 마이그레이션 리뷰 표준(Brain)이 정의되지 않아서.

## 3. PDM (Prevent, Detect, Mitigate) 분류 체계
Action Item(재발 방지 대책)을 도출할 때는 반드시 아래 세 가지 범주로 나누어 제안하십시오.
*   **Prevent (예방):** 장애의 근본 원인을 제거하여 다시는 발생하지 않도록 하는 조치.
*   **Detect (탐지):** 장애가 다시 발생하더라도, 고객이 알기 전에 모니터링 시스템(MTTD)이 먼저 잡아내도록 하는 조치.
*   **Mitigate (완화):** 탐지된 장애가 확산되지 않도록 시스템을 격리하거나(Circuit Breaking), 자동 복구(MTTR)되게 하는 조치.
