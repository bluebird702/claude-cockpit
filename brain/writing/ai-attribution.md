# AI 협업 표기 표준

> 사람이 Claude Code 등 AI 와 **함께** 작성한 산출물은 그 사실을 표기합니다. 직접 쓴 것과
> 구별되도록 — 커밋의 `Co-Authored-By` 와 같은 역할을 산문·코멘트·문서에도 일관되게 적용합니다.
> 세션 시작 시 자동 로드되므로 AI 는 별도 지시 없이 이 규칙을 적용합니다.

## 원칙

- **AI 가 (공동)작성한 것만 표기**한다. 사람이 직접 타이핑한 글에는 붙이지 않는다 → **표기 유무로 구별**.
- **author 는 사람 그대로** 두고, "AI 협업 여부"만 남긴다 (소유권 이전이 아니라 투명성).
- GitHub 봇 신원(예: `my-agent[bot]`)으로 게시되는 **에이전트** 산출물은 이미 봇으로 구별되므로 별도 표기 불필요. 이 표준은 **사람이 AI 와 함께** 만든 산출물이 대상.

## 대상별 표기

| 대상 | 표기 방법 |
|------|-----------|
| **커밋** | `Co-Authored-By: <모델명> <noreply@anthropic.com>` (구조적 — @writing/commit-message.md) |
| **GitHub 코멘트·이슈·PR 본문** | 하단 footer 한 줄: `— 🤖 <모델명> 협업` |
| **문서 (md·ADR·글)** | frontmatter `assisted_by: <모델명>` 또는 본문 하단 `— 🤖 <모델명> 협업` |

- `<모델명>` 은 실제 사용 모델 (예: `Claude Opus 4.8`).
- footer 는 본문과 빈 줄 하나로 구분한다.

## 적용 규칙 (AI·에이전트용)

- 사용자를 대신해 GitHub 코멘트/이슈/PR 텍스트를 **게시**하거나 문서를 **작성**할 때, 위 footer/frontmatter 를 자동으로 붙인다.
- 사용자가 문구를 직접 주고 그대로 게시만 요청한 경우(= 사람이 쓴 글)에는 붙이지 않는다.
- 애매하면 붙인다 — 과소표기보다 **과대표기가 안전**(투명성 우선).

## 예시

코멘트:
```
이 설계는 fail-closed 검증으로 가는 게 맞습니다. value class 는 여기선 강제력이 없습니다.

— 🤖 Claude Opus 4.8 협업
```

문서 frontmatter:
```yaml
---
title: 서버리스 에이전트 셋업
assisted_by: Claude Opus 4.8
---
```
