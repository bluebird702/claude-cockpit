# AI 에이전트 워크플로 표준

> AI 에이전트(서브에이전트·백그라운드 작업·자동화 훅)에게 일을 맡길 때의 **위임·검증·운영** 기준입니다.
> 데이터 경계(무엇을 보낼 수 있는가)는 @ai/ai-usage.md, 철학적 근거는 @philosophy.md § AI 원칙.

## 위임 원칙

| 맡긴다 | 직접 한다 |
|--------|-----------|
| 병렬 탐색·수집 (여러 파일/영역 읽기) | 최종 판단·승인 (머지, 배포, 표준 변경) |
| 초안 생성 (PRD·리뷰·문서 스켈레톤) | 되돌리기 어려운 결정 (ADR 대상) |
| 반복·기계적 변환 (마이그레이션, 포맷) | 시크릿·프로덕션 접근 |
| 측정 실행 (lint·coverage·CVE 스캔) | 측정 결과의 해석과 트레이드오프 판단 |

- **무인 자기수정 금지**: 에이전트가 표준·룰셋·훅을 스스로 승격/변경하지 않습니다. **초안까지만, 적용은 사람 승인** (`/review:promote` 패턴).

## 검증 게이트

1. **산출물 행위를 단언** — "완료했다" 는 검증이 아닙니다. tautological 검증 금지(@testing/testing-guidelines.md 원칙의 AI 판): 실제 출력·diff·테스트 결과를 확인합니다.
2. **산술·점수는 스크립트로** — LLM 암산 금지. 점수·집계는 결정론 스크립트가 계산합니다.
3. **리뷰어 자체를 측정** — 리뷰 에이전트는 골든셋(라벨된 결함)으로 precision/recall 을 재고, 원장(ledger)으로 발견의 생애(`new/open/fixed`)를 추적합니다.
4. **모델 버전 태깅** — 에이전트 모델이 바뀌면 골든셋 재통과 전까지 그 점수를 신뢰하지 않습니다. 회귀 시 규칙보다 프롬프트/앵커를 먼저 의심합니다.

## 자동 오케스트레이션 파이프라인

> 에이전트들을 잇는 자동 루프(트리아지→배정→구현→리뷰→머지)를 만들 때의 관례.
> provenance: 무인 개발 루프 구축 실사고(2026-07-18) — 각 항목은 값을 치르고 배운 것.

1. **"완료" 신호는 부분 검증을 완료로 표기하지 않는다** — "머지 준비" 는 리뷰 통과 **AND** 전체 체크 GREEN 둘 다일 때만. 새 커밋이 오면 즉시 강등하고, 이전 완료 표기에 무효 표시를 붙인다. 신호가 항상 "현재 상태 기준 참"이어야 사람이 그 신호 하나만 보고 행동할 수 있다. (실사고: 체크 미완인데 완료 멘트 → 반복 혼란)
2. **상태는 오케스트레이터가 아니라 진실원에** — 작업 상태를 이슈/라벨 같은 외부 진실원에 두면 실행자(러너·프로세스)는 소모품이 된다. 크래시·리밋으로 죽어도 회수 루프가 재개하므로 유실 0. 실행자에 상태를 두면 그것이 죽을 때 작업도 죽는다.
3. **자동수정은 1회 재시도 후 에스컬레이션** — 체크 실패를 곧바로 사람/작성자에게 던지지 말고 1회 자동 재시도(플레이키·리밋 블립 필터). 재시도도 실패할 때만 에스컬레이션. 단 재시도 횟수 가드(run_attempt)로 폭주 차단.
4. **루프 공회전 차단: 캡 + dedup + 심의 컨텍스트** — LLM 리뷰어가 이미 채택·검증·보류된 지적을 재생성하면 자동수정이 무한 공회전한다. (a) 하드 캡(N회), (b) 지적 세트 해시로 동일 재발 차단, (c) 이전 심의 기록을 리뷰어 컨텍스트에 주입 — 3중으로 막는다.
5. **사람 개입은 1급 시민** — "자동 아니면 수동" 이 아니라, 자동 루프를 **멈추는 신호**(예: hold 라벨)를 두어 사람이 판단할 공간을 만든다. 개입 중엔 자동 승격·통지를 중단하고, 개입이 끝나면 자동 검증 루프가 스스로 재개한다.
6. **횡단 드리프트는 주기 전체리뷰로 보완** — diff 단위 리뷰는 시스템 횡단 이슈(패턴 확산·설정 드리프트)를 구조적으로 놓친다. 전체 리뷰를 **변경량 비례**(달력 아님)로 주기 실행해 2차 그물을 친다. 비용 게이트는 주기, **가치 게이트는 severity 필터**(크리티컬만 액션화) — 둘을 분리하면 "덜 자주 돌려도 잃는 게 적다".

## 백그라운드 에이전트 운영

- 진행 상황은 output 파일을 **1분 간격**으로 확인하고, 현재 상태(작성 중인 파일·빌드 결과·남은 작업)를 사용자에게 보고합니다.
- **5분 이상** 걸리면 자동으로 진행 상황을 확인·보고하고, **10분 이상**이면 중단 여부를 사용자에게 확인합니다.
- 컨텍스트 절약: 파일 먼저 다 만들고 빌드는 마지막 1회. 코드 작성 전 같은 디렉토리 기존 파일 1-2개를 먼저 읽습니다.
