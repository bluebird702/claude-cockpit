# PRD 작성 가이드 (1인 창업 에디션)

> 1인 창업에서 PRD 의 목적은 **자기 자신과의 계약**입니다. 2일 뒤 "왜 이걸 하고 있지?" 를 막는 도구.

## 언제 PRD 를 쓰는가

- **2일 이상** 걸릴 것으로 예상되는 기능 작업
- **2인 이상** 의 컴포넌트를 건드리는 작업 (예: API + 프론트 + 마이그레이션)
- **외부 의존성** 이 있는 작업 (결제, 써드파티 API)
- **실험성 작업** — 실패 기준을 사전에 박아두기 위해

짧은 버그 픽스, 리팩터링, UI 텍스트 수정은 PRD 없이 진행. 대신 커밋 메시지로 맥락 남깁니다.

## 1-페이지 PRD 형식

10페이지 PRD 는 1인 창업에서 시간 낭비입니다. **A4 1장 안에** 끝냅니다.

```markdown
# [기능명]

**작성일**: YYYY-MM-DD
**상태**: Draft / Approved / Shipped / Killed

## 1. 문제 (Problem)
<현재 무엇이 문제인가? 누가 불편한가? 2-3문장>

## 2. 대상 사용자 (Who)
<누가 이 기능을 쓸 것인가? 페르소나 또는 세그먼트>

## 3. 성공 지표 (Success Metric)
- **Goal**: <숫자 + 기간> (예: "런치 2주 내 활성 유저 중 30% 사용")
- **Guardrail**: <해치면 안 되는 것> (예: "가입 전환율 -1pp 이상 하락 시 롤백")

## 4. 범위 (In Scope)
- <할 것 3-5개>

## 5. 범위 외 (Out of Scope) ★
- <의도적으로 안 할 것 3-5개>

## 6. 해결책 개요 (Solution Sketch)
<어떻게 풀 것인가? 다이어그램 1개 또는 5줄 이내 설명>

## 7. 리스크 & 롤백 기준
- 리스크: <무엇이 잘못될 수 있는가>
- 롤백 기준: <어떤 숫자가 나오면 되돌리는가>

## 8. 오픈 질문
- <결정 못 한 것>
```

## 섹션별 원칙

### 문제 (Problem) 섹션

- **해결책이 아닌 문제** 로 서술. "검색 기능이 필요하다" ❌ → "사용자가 N주 전 대화를 찾지 못한다" ✅
- **증거 제시**: 사용자 피드백, 지표, 관찰. 추측이면 "가설" 이라고 명시.

### 범위 외 (Out of Scope) 섹션 ★

가장 중요한 섹션입니다. 1인 창업에서 기능이 부풀어 오르는 걸 막는 유일한 방법.

- **의도적으로 안 할 것** 을 나열. "하지 않을 것" 이 "할 것" 보다 많아야 건강한 PRD.
- 예: "검색 필터, 저장된 검색, 자동완성 — 다음 이터레이션에서 검토"
- 구현 중 "이것도 넣을까?" 생각이 들면 Out of Scope 에 명시적으로 추가.

### 성공 지표

- `@standards/product/metrics.md` 의 Goal/Guardrail 프레임을 따릅니다.
- **지표 없는 PRD 는 반려 (자기 자신이 자기 자신에게)**.

### 롤백 기준

- "뭔가 이상하면 롤백" ❌ → "에러율 >1% OR p95 >2x 평소 → 5분 내 롤백" ✅
- 숫자로 쓰지 못하면 런치하지 않음.

## PRD 라이프사이클

```
Draft (작성) → Approved (본인 재확인 후) → Shipped → [성공 지표 측정 후] → Kept / Killed
```

- **Killed** 로 끝나는 것을 부끄러워하지 않음. 지표가 안 나오면 명시적으로 죽입니다.
- Killed 된 PRD 도 지우지 않음. "왜 실패했는가" 가 다음 PRD 의 입력.
- Kept/Killed 판정 도구: `/prod:metrics-verdict` (측정 기간 종료 후 실측값으로 기계적 판정).

## 파일 위치

- 프로젝트별: `docs/prd/NNNN-title.md` (NNNN 연번)
- cockpit 자체의 대형 변경도 PRD 가 필요할 수 있음 → `docs/prd/` 에 저장

## Claude Code 연동

- **초안 생성**: `/plan:prd-draft <한 줄 아이디어>` — 아이디어 → PRD 뼈대.
- **결정 기록**: PRD 에서 나온 비자명한 선택은 ADR 로 승격 (`@standards/management/decision-log.md`).
