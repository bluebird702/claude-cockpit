# Architecture: Internals

이 문서는 `claude-cockpit`이 작동하는 근본적인 메커니즘을 설명하는 시스템 아키텍처 문서입니다. (오픈소스 기여자 및 고급 사용자를 위한 가이드입니다.)

## 1. 링킹(Symlinking) 시스템의 비밀
`claude-cockpit`은 여러분의 레포지토리에 직접 설치되는 것이 아닙니다. 
우리의 설치 스크립트(`global-install.sh`)는 여러분의 홈 디렉토리 아래에 있는 `~/.claude/` 환경으로 **심볼릭 링크(Symbolic Link)**를 꽂아 넣습니다.

### 왜 이렇게 설계했나요?
1. **단일 출처 (Single Source of Truth):** 스킬이나 규칙이 업데이트되면, 레포지토리에서 `git pull`을 받는 즉시 터미널의 Claude Code 환경에 실시간으로 반영됩니다.
2. **플랫폼 독립성 (Platform Agnostic):** 이 레포지토리의 파일들은 순수한 Markdown 텍스트일 뿐입니다. 현재는 `claude-code` CLI에 맞춰 링킹되지만, 언제든 Cursor, Github Copilot, Aider 등 다른 AI 에이전트의 폴더 구조에 맞춰 링크 경로만 바꾸면 똑같이 동작합니다.

## 2. 다국어(I18n) 스위칭 구조
글로벌 오픈소스 생태계를 위해 Cockpit은 독창적인 다국어 시스템을 가집니다.

*   `skills/` 하위에는 영어 원본(`.md`)과 번역본(`.ko.md`, `.ja.md` 등)이 섞여 존재합니다.
*   **스마트 링킹:** `install.sh --lang=ko` 옵션을 사용하면, 인스톨러는 `.ko.md` 파일들만 쏙쏙 골라내어 `~/.claude/commands/` 에 `.md` 확장자로 이름표를 바꿔 달아줍니다.
*   결과적으로 AI(Claude)는 "나는 지금 `ideation.md`를 읽고 있다"고 착각하지만, 실제로는 한국어 번역본을 읽게 되는 우아한 트릭입니다.

## 3. Core(기계)와 Docs(인간)의 분리
*   **`brain/`**: AI가 읽고 따를 강제적 규칙입니다. 여기에 말을 예쁘게 쓰지 마세요. 토큰을 아끼기 위해 극도로 건조하게 작성해야 합니다.
*   **`docs/`**: 바로 이 문서처럼, 인간이 읽고 이해하기 위한 매뉴얼입니다. AI의 컨텍스트 창에는 기본적으로 들어가지 않습니다.
