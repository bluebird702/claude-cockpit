# 문서 스타일 가이드

> 대상: 모든 한글 기술 문서 (CLAUDE.md, README, guidelines, design docs, ADR).

## 기본 원칙

1. **한 문서 = 한 목적**. 목차 없이도 제목만 보고 용도를 알 수 있어야 합니다.
2. **읽는 사람의 시간 우선**. 배경 설명보다 결론·체크리스트·예시를 앞에 둡니다.
3. **Claude가 실수할 지점**을 먼저 적습니다. 일반론은 생략하거나 링크로 대체합니다.

## 파일 구조

```markdown
# 제목

> 한 줄 목적 (대상 독자 포함)

## 빠른 시작 / TL;DR
<2-5줄 또는 코드 블록 하나>

## 규칙 / 절차
<핵심 내용. 테이블·체크리스트 우선>

## 예시

## 관련 문서
- @brain/CLAUDE.md
- @docs/dev/project-structure.md
```

- 루트 CLAUDE.md 는 **200줄 이하**. 초과 시 `.claude/rules/` 또는 `@파일경로` 로 분리.
- 자주 변하는 API 목록·환경변수 전체는 인라인 금지 → 링크.

## 톤

- **존댓말**. 명령형은 "합니다/하세요" 로 끝맺어 단호하게.
- **주어 생략** 가능. "당신" 대신 "작업자" 또는 생략.
- **코드 식별자**는 영어 유지. 주석·설명은 한글.
- **불필요한 감탄사/형용사 금지**. "매우", "정말", "아주" 는 대부분 삭제 대상.

### 좋은 예 / 나쁜 예

- ❌ "이 매우 중요한 설정을 정말 반드시 꼭 지켜야 합니다!"
- ✅ "이 설정을 지키지 않으면 프로덕션 빌드가 실패합니다."

## 리스트와 테이블

- **비교**가 필요하면 테이블, **순서**가 있으면 번호 리스트, **병렬 나열**은 불릿.
- 테이블 열은 4개 이하가 읽기 좋음. 그 이상이면 테이블을 쪼개거나 문단으로.

## 링크·참조

- **내부 참조**는 `@상대경로` (Claude Code 의 자동 로드 문법) 또는 마크다운 링크.
- **외부 링크**는 URL 을 그대로 노출하지 말고 `[제목](URL)` 형태.
- **파일·라인**을 지칭할 때는 ``file_path:line_number`` 포맷 (예: `services/auth/src/login.ts:42`).

## 코드 블록

- 언어 지정 필수: ` ```bash`, ` ```kotlin`, ` ```json`
- 실행 가능한 예시는 **주석으로 기대 출력**을 포함
- 환경변수 예시는 실제 값 대신 `<YOUR_TOKEN>` 또는 `${GITHUB_TOKEN}`

## 금지 항목

- 코드에서 유추 가능한 내용 (표준 언어 컨벤션, 파일 용도 나열)
- 여러 문서에 동일 규칙을 복붙 → standards 로 이관하고 링크
- 상대적 시간 ("최근", "요즘", "다음 주") → 절대 날짜로 (`2026-03-05`)
- 고유명사 철자 혼동 (`claude-cockpit`, `Claude Code` 등 공식 표기 사용)

## 자기 점검 체크리스트

문서를 커밋하기 전 `/docs:claude-docs-review` 를 실행하거나 아래를 직접 확인:

- [ ] 제목 한 줄만 봐도 용도가 명확한가
- [ ] 코드에서 유추 가능한 내용이 포함되어 있지 않은가
- [ ] 200줄을 넘지 않는가 (CLAUDE.md 의 경우)
- [ ] 깨진 링크가 없는가 (`grep -n '@[a-z]' ` 및 수동 확인)
- [ ] 존댓말·한글 규칙을 따르는가
