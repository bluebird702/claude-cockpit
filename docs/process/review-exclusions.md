# 리뷰 제외 항목

> 아키텍처/코드 리뷰 시 **의도적으로 평가에서 제외**할 항목을 프로젝트별로 정의한다.
> 이 파일은 **템플릿** — 프로젝트에 맞게 채운다(아래 예시는 형식 참고용).

## 왜 명시하나

"추후 구현 예정"·"현재 규모에서 불필요"인 항목을 리뷰어가 반복 지적하면 노이즈다.
제외를 명시하면 리뷰가 **진짜 문제에 집중**한다. 단, 제외는 **부채의 인정**이지 면죄부가 아니다 — 사유·범위·재검토 시점을 함께 적는다.

## 형식 (예시)

| 항목 | 사유 | 범위 | 재검토 트리거 |
|-----|-----|------|--------------|
| (예) 분산 캐싱 | 추후 구현 | 서비스 A·B | 트래픽 X 도달 시 |
| (예) 통합 테스트 | MVP 단계 | 전체 | 정식 런치 전 |
| (예) API 버저닝 v2 | v1만 운영 | Gateway | 외부 소비자 생길 때 |

## 원칙

- 제외는 **기록**한다(구두 금지) — 리뷰어가 이 파일을 참조.
- 제외마다 **재검토 트리거**를 단다(무기한 제외 금지).
- **보안·데이터 손실·법적 리스크 항목은 제외 불가.**

---

> 회사/프로젝트 고유 제외 목록은 **각 프로젝트 레포**에서 이 템플릿을 채워 관리한다(cockpit엔 두지 않음).
