# 코드 품질 리뷰

> ⚠️ **Standards 준수 필수** — 코드 판단 기준은 standards를 우선합니다.
> @standards/CLAUDE.md · @standards/coding/coding-guidelines.md

SOLID 원칙, 가독성, 안티패턴, standards 위반 여부를 심층 점검합니다.

$ARGUMENTS
- `deep` — 심층 모드 (문제 코드 + 개선 코드 포함)
- **서비스명 또는 경로** — 해당 범위만 분석
- 인자 없음 → 프로젝트 전체 요약
- 예: `/review:code`, `/review:code deep src/account`

## Step 1: 컨텍스트 파악

- 언어, 프레임워크, 스타일 가이드 (ktlint, eslint, rubocop 등)
- standards 문서의 코딩 규칙
- 프로젝트의 지배적 패러다임 (OOP / FP / 하이브리드)

## Step 2: 체크리스트 (20항목)

### SOLID (5)
| # | 항목 | 점검 내용 |
|---|------|----------|
| 1 | SRP | 함수/클래스가 단일 변경 이유를 가지는가 |
| 2 | OCP | 새 동작 추가 시 기존 코드 수정 없이 확장 가능한가 |
| 3 | LSP | 하위 타입이 상위 타입 계약을 깨지 않는가 |
| 4 | ISP | 클라이언트가 사용하지 않는 메서드에 의존하지 않는가 |
| 5 | DIP | 고수준 모듈이 추상에 의존하는가 (구체 타입 직접 의존 금지) |

### 가독성·네이밍 (5)
| # | 항목 | 점검 내용 |
|---|------|----------|
| 6 | 의도 드러내는 이름 | 축약·모호 이름(`data`, `mgr`, `tmp`), Hungarian 표기 |
| 7 | 함수 길이 | 권장 ≤20줄, 절대 ≤50줄 |
| 8 | 순환 복잡도 | 메서드당 ≤10 |
| 9 | 파라미터 개수 | ≤3 권장, ≥5는 객체화 |
| 10 | 깊은 중첩 | 중첩 ≥4, 조기 반환·가드 절로 해소 |

### 안티패턴 (10)
| # | 항목 | 점검 내용 |
|---|------|----------|
| 11 | 중복 코드(DRY) | 3회 이상 유사 블록 |
| 12 | 매직 넘버/문자열 | 리터럴 상수 미추출 |
| 13 | Boolean 파라미터 | 플래그 인자 → enum/메서드 분리 |
| 14 | 가변성 남용 | var / mutable 컬렉션 기본 사용 (불변 우선 원칙) |
| 15 | null/Optional 남용 | `!!`, `get()` 직접 호출, Optional 체이닝 누락 |
| 16 | 예외 삼키기 | `catch {}`, `catch { log }` 후 복구 없음 |
| 17 | 죽은 코드 | 미사용 import, 미호출 private, 주석된 코드 |
| 18 | 주석 부채 | 코드와 어긋난 주석, 자명한 주석, TODO 방치 |
| 19 | 조기 추상화 | 1회 사용되는 인터페이스·제네릭 |
| 20 | God Object | 수백 줄 클래스, 필드 수십 개, 공용 유틸 덤프 |

## Step 3: 에이전트 위임

`pr-review-toolkit:code-reviewer` 에이전트에게 위임. 프롬프트에 포함:
- Step 1 컨텍스트 한 줄 요약
- 분석 대상 경로
- Step 2 체크리스트 20항목
- standards 문서의 규칙 우선 적용 지시
- Step 4 출력 형식 지시

**빌드/테스트 실행 금지, 코드 읽기만.**

## 점수 산정 규칙

| 섹션 | 항목 수 | 배점 |
|------|---------|------|
| SOLID | 5 | 25점 |
| 가독성·네이밍 | 5 | 25점 |
| 안티패턴 | 10 | 50점 |

- **N/A 처리**: 언어·패러다임상 해당 없는 항목은 N/A로 표시하고 해당 섹션 분모에서 제외
  - 예외 없는 언어(Go, Rust error return) → #16(예외 삼키기) 판단 기준 조정
  - FP 중심 언어 → #14(가변성 남용) 판단 시 언어 관용구 기준으로 적용
- **섹션 점수**: `(통과 항목 수 ÷ (섹션 전체 − N/A)) × 섹션 배점`
- **종합 점수**: 3개 섹션 점수 합 (소수점 반올림)

## Step 4: 출력 형식

**요약 모드:**
```markdown
## 코드 품질 리뷰 결과

### 점수: XX/100
- SOLID: XX/25점 (통과 N/5)
- 가독성: XX/25점 (통과 N/5)
- 안티패턴: XX/50점 (통과 N/10, N/A K항목 제외)

### 강점 (2-3개)

### 문제 (최대 5개, 심각도순)
| # | 카테고리 | 파일:줄 | 설명 |

### 한 줄 요약
```

**심층 모드:** 요약 + 각 문제마다 아래 블록
```markdown
> *위치*: [파일:줄]
> *카테고리*: [SRP / 가독성 / 중복 / ...]
> *현재*: (문제 코드)
> *문제*: (원칙/규칙 위반 이유)
> *개선*: (개선 코드)
```

## Step 5: 드릴다운

- 테스트가 없어 리팩토링 불가 → `/review:test`
- 구조적 문제(계층 혼재) → `/review:architecture`
- 예외 처리 관련 문제 다수 → `/review:security`
