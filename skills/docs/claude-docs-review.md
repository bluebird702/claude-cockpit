# CLAUDE.md 문서 검토

> ⚠️ **Standards 준수 필수** — 문서 구조 판단 기준은 standards를 우선 참고합니다.
> @standards/CLAUDE.md

현재 프로젝트의 모든 CLAUDE.md 파일을 검토하고 점수화합니다.

## 검토 절차

### 1. 프로젝트 컨텍스트 파악

- 프로젝트의 언어, 프레임워크, 빌드 도구
- 디렉토리 구조 (모노레포/멀티레포/단일 서비스)
- `.claude/rules/` 디렉토리 존재 여부 및 내용
- 프로젝트 내 가이드라인/문서 디렉토리 존재 여부

### 2. 파일 수집

- 루트 CLAUDE.md
- 하위 디렉토리의 CLAUDE.md (서비스/모듈별)
- `.claude/rules/*.md` (있는 경우)
- `~/.claude/CLAUDE.md` (사용자 레벨, 있는 경우)

### 3. 평가 기준 (100점 만점)

| 항목 | 배점 | 평가 내용 |
|------|------|----------|
| **필수 정보 완성도** | 25점 | 빌드/테스트 명령어, 비명백한 동작/함정, 아키텍처 결정, 코드 스타일(기본과 다른 경우만) |
| **토큰 효율성** | 25점 | 200줄 이하, 코드에서 유추 가능한 내용 제외, 중복 없음 |
| **구조 및 모듈화** | 20점 | `.claude/rules/` 활용, `@파일경로` import, path-specific rules |
| **정보 밀도** | 15점 | "이 없으면 Claude가 실수할까?" 테스트 통과, 테이블/간결한 형식 |
| **일관성** | 15점 | 여러 CLAUDE.md 간 동일 패턴, 루트↔하위 역할 분리 |

### 4. 체크리스트

**필수 정보 체크**
- [ ] 빌드/테스트 실행 명령어가 있는가?
- [ ] 코드 스타일 규칙이 있는가? (언어 기본과 다른 부분만)
- [ ] 비명백한 동작이나 함정이 문서화되어 있는가?
- [ ] 아키텍처 결정사항이 있는가?
- [ ] 저장소 에티켓이 있는가? (브랜치, 커밋, PR)

**토큰 낭비 체크**
- [ ] Claude가 코드에서 유추할 수 있는 내용이 포함되어 있는가?
- [ ] 자주 변경되는 정보가 직접 작성되어 있는가?
- [ ] 상세한 API 문서나 긴 튜토리얼이 인라인으로 포함되어 있는가?
- [ ] 루트 CLAUDE.md가 200줄을 초과하는가?

**중복 체크**
- [ ] 동일한 규칙이 여러 CLAUDE.md에 반복되는가?
- [ ] 루트 CLAUDE.md와 하위 CLAUDE.md 간 역할이 명확히 분리되어 있는가?

**구조 최적화 체크**
- [ ] 200줄 초과 시 `.claude/rules/` 로 분리되어 있는가?
- [ ] 외부 문서를 `@파일경로` 로 참조하고 있는가?
- [ ] standards submodule을 통해 공통 규칙을 로드하고 있는가?

## 출력 형식

```markdown
## CLAUDE.md 종합 검토 결과

### 전체 점수: XX/100
| 평가 항목 | 점수 | 비고 |

### 파일별 상세
| 파일 | 줄 수 | 주요 강점 | 개선점 |

### 토큰 낭비 항목 (제거/이동 권장)
| 파일 | 줄 번호 | 내용 요약 | 사유 | 권장 조치 |

### 개선 방안
#### P0 - 즉시 적용
#### P1 - 권장
#### P2 - 선택
```
